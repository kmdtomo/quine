# Quine マニフェスト

> エンジニアの技術スタックを起点に、人とプロダクトを可視化する**運動**。

これは機能仕様ではない。**Quine がなぜ存在するのか、何を破壊しに来たのか、何を絶対にやらないか**を定めた最上位ドキュメント。すべての設計判断はここに従う。

---

## なぜ存在するのか

エンジニア界には、4つの **FOMO (Fear of Missing Out)** が蔓延している:

| 種類 | 内容 |
|------|------|
| **観測 FOMO** | 他社・他人が何で作っているか見えない |
| **承認 FOMO** | 自分が作ったものが誰にも届かない |
| **接続 FOMO** | 優秀なエンジニアの繋がりに自分は入れていない |
| **学習 FOMO** | 何を学ぶべきか分からない |

根源は一つ。**技術スタックがブラックボックス化されている。**

この不健全さは、学習・承認・採用すべての歪みを生んでいる。Quine はこの不健全さに対する運動である。

---

## 何を破壊するか

- **読まれない README** — 書いても誰も見ない、努力が報われない仕組み
- **雑魚いポートフォリオサイト** — 入力がだるく、UI が弱く、就活/転職用に堕ちている
- **会社と個人の分断** — 同じエンジニアの仕事なのに別アカウントで分けられている
- **採用目線のキャリア SNS** — LinkedIn / Wantedly のような職歴ナラティブ
- **ぐだぐだの技術面接** — 技術を見る場がないから抽象論で人を採るしかない
- **技術スタックを隠す企業** — 隠さなければセキュリティが保てないなら、その時点で詰んでいる

## なぜ「隠す」が悪なのか

セキュリティ業界には *security through obscurity*(隠蔽による安全) というアンチパターンがある。**「技術を隠すから安全」は最弱の防御**だ。

OpenSSL、Linux、Postgres、世界の重要インフラはすべて中身が公開されている。技術スタックを隠さないと安全を保てない企業は、設計が脆弱なだけだ。**淘汰されるべきである。**

---

## 絶対にやらないこと

- **評価しない** — いいね、星、ランキング、フォロワー数を置かない
- **ジャッジしない** — 「優秀さ」をプラットフォームが判定しない
- **転職プラットフォームにしない** — 求人連携、スカウト送信機能は持たない
- **誰でも繋がれるようにしない** — 繋がりは量ではなく質。広く浅くは作らない
- **ユースケースを限定しない** — 学習・表現・採用、誰がどう使うかは関知しない

## 絶対にやること

- **圧倒的 UI と世界観で読ませる** — コンテンツの強度ではなく、場の強度で価値を立たせる
- **AI で自動化する** — 設定を最小化、入力ゼロで技術スタックを浮かび上がらせる
- **会社と個人の境を消す** — アカウント種別を持たない、すべて「ユーザー」
- **限定的な繋がりだけを許す** — 数を制限する。優秀な周辺と繋がってこそ価値が立つ
- **フローだけを完璧にする** — ユースケースは限定しないが、流れは妥協しない

---

## 設計の根底にある問い

判断に迷ったら、これに戻る:

1. **「これは FOMO を解消するか?」** YES なら作る、NO なら作らない
2. **「これはエンジニアを評価する仕組みになっていないか?」** なっていたら却下
3. **「これは技術スタックの透明性を高めるか?」** YES が望ましい
4. **「これは入力をだるくしないか?」** だるくするなら自動化を考える
5. **「これは繋がりを薄めないか?」** 薄めるなら制限を入れる
